# 商机列表 · 手工测试用例

> 适用版本：商机动态 / 固定动作字段校验 / 批量操作 上线后
> 测试入口：http://localhost:5173/opportunities
> 后端地址：http://localhost:3000/api/v1

## 一、测试准备

### 1.1 测试账号

密码统一为 `123456`。

| 账号 | 角色 | 商机权限 | 数据范围 |
|---|---|---|---|
| admin | 系统管理员 | 全部 | 全部 |
| sales01 | 销售 | 查看 / 新建 / 编辑（无删除、无回退） | 仅本人 |
| support01 | 业务支撑 | 查看 / 编辑（无新建、无删除） | 全部 |
| manager01 | 管理层 | 查看 / 新建 / 编辑 / 回退（无删除） | 全部 |
| presales01 | 售前 | 查看 / 编辑 | 自定义共享 |
| ecosystem01 | 生态 | 仅查看 | 自定义共享 |

### 1.2 数据准备

- 用 admin 新建 2~3 条测试商机（不同阶段、不同负责人）。
- 删除、转公海、批量操作会真实改数据，建议先准备独立测试数据。
- 建议准备一条「进行中且存在未完成固定动作」的商机，用于推进校验测试。

### 1.3 环境检查

- [ ] 后端 `http://localhost:3000/api/v1/health` 正常
- [ ] 前端 `http://localhost:5173` 可访问
- [ ] 已用 admin 登录，能进入「商机中心 → 商机列表」

## 二、功能点与操作步骤

### A. 页面入口与整体

| # | 功能点 | 操作 | 预期结果 | 结果 |
|---|---|---|---|---|
| A1 | 进入商机列表 | 左侧菜单「商机中心 → 商机列表」 | 页面标题为「商机列表」，右侧显示数据范围徽标 | ☐ |
| A2 | 数据范围徽标 | 分别用 admin / sales01 登录查看 | admin 显示全部范围；sales01 显示本人范围且列表只剩自己的商机 | ☐ |

### B. 顶部工具栏

### G. 推进校验弹窗（列表页「推进」）

| # | 功能点 | 操作 | 预期结果 | 结果 |
|---|---|---|---|---|
| G1 | 完成度提示 | 打开推进弹窗 | 显示当前阶段 → 下一阶段、固定动作完成度（如 7/8）及缺失项数量 | ☐ |
| G2 | 动作清单 | 查看列表 | ✅ 已完成项显示已填值；⬜ 未完成项高亮 | ☐ |
| G3 | 去填写（内置 / 自定义字段） | 点未完成字段右侧「去填写」 | 关闭弹窗并跳 `/opportunities/{id}/edit?focus=字段键`，页面滚动到该字段并聚焦 | ☐ |
| G4 | 去处理（系统动作） | 对行为 / 方案 / 报价 / 竞对 / 合同类缺失项点「去处理」 | 跳详情并直接切到对应页签：行为记录→activity、方案报价→assets、竞争对手→competitors、合同→contracts | ☐ |
| G5 | 补齐后推进 | 填完缺失项后再打开弹窗点「推进」 | 推进成功，阶段与阶段历史更新 | ☐ |
| G6 | 强制推进 | 管理员 / 有回退权限账号点「强制推进」并填原因 | 跳过校验推进成功并记录原因；普通销售无法强制 | ☐ |

> 回归重点：G4 的页签映射此前在列表页写成了不存在的页签名（会退回「固定动作」），已修正。

## 三、建议测试顺序

1. admin：新建 → 筛选 → 推进（含去填写 / 去处理）→ 编辑 → 标记失败 → 批量转移 / 转公海 / 删除
2. sales01：验证数据范围仅本人、无删除 / 无回退按钮
3. manager01：验证全量数据范围、强制推进
4. ecosystem01：验证只读
5. 视图配置：列顺序、默认筛选、默认排序、另存为、记住视图
6. 漏斗看板：推进弹窗与「去填写 / 去处理」联动

## 四、已知限制

- 表格表头不支持点击排序，排序统一通过「配置视图 → 默认排序」设置。
- 批量操作单次最多 200 个商机。
- 批量操作逐条鉴权，部分失败时以提示形式返回首个失败原因。
